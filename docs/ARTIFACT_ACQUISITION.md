# Large-artifact acquisition and reconstruction

This document defines how non-Git artifacts enter the public TSPG reproducibility boundary. Exact identities are authoritative; filenames and storage locations are secondary.

The machine-readable source is `../manifests/LARGE_ARTIFACTS_SHA256.csv`.

The compact H1-0015--H1-0019 runtime evidence ZIPs are identified by `../manifests/EVIDENCE_ARCHIVES_SHA256.txt`. They are the authoritative run-evidence layer and will be deposited with the immutable archival release rather than inserted into ordinary Git history.

## Integrity rule

For every downloaded or regenerated binary, calculate SHA-256 and compare it with `../manifests/LARGE_ARTIFACTS_SHA256.csv`. A matching filename with a non-matching SHA-256 is **not** the study artifact.

Where a regenerated artifact is expected to be numerically equivalent but not byte-identical because of environment/library differences, it must not silently replace the authoritative archived object. Such a reproduction should be reported separately with its environment record and numerical comparison to the locked result.

## Release state

Storage URLs for the numerical archival assets remain intentionally `PENDING_ARCHIVAL_UPLOAD` until the GitHub tree is frozen and the matching Zenodo archival record is created. This prevents mutable shared-folder locations from becoming part of the permanent provenance chain.
